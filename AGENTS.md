# AGENTS.md

## Project overview

This is a small desktop computer-vision project that counts free parking spaces in a
video feed using classical image processing (no machine learning). It is written in
Python with OpenCV and cvzone.

Note: the GitHub repository name mentions "Django", but there is no Django (or any
web) code in this project — it consists of two standalone OpenCV scripts.

How it works:

1. `ParkingSpacePicker.py` is a one-time setup tool. It opens the reference image
   `image.png` and lets the user mark parking-space rectangles with mouse clicks
   (left-click adds a space, right-click removes one). The positions are persisted
   as a pickled list of `(x, y)` tuples in the file `CarParkingPosition`.
2. `main.py` reads `carPark.mp4` in a loop, preprocesses each frame (grayscale →
   Gaussian blur → adaptive threshold (inverse) → dilation), then for every marked
   parking position crops that region and counts non-zero pixels with
   `cv2.countNonZero`. A count below `1000` means the space is free (green
   rectangle), otherwise occupied (red rectangle). A `free: N/total` overlay is
   drawn on the frame.

Both scripts share the fixed parking-space rectangle size `width, height = 107, 48`
and read/write the same `CarParkingPosition` pickle file, so positions picked in the
picker must use the same dimensions as `main.py` expects.

## Repository layout

| Path                   | Purpose                                                          |
| ---------------------- | ---------------------------------------------------------------- |
| `main.py`              | Runs the parking-space detection on the video feed.              |
| `ParkingSpacePicker.py`| Interactive tool to mark/unmark parking spaces on `image.png`.   |
| `CarParkingPosition`   | Pickled `list[tuple[int, int]]` of space top-left corners (data, generated by the picker). |
| `image.png`            | Reference frame (1100x720) used by the picker.                   |
| `carPark.mp4`          | Input video (~10 MB) analyzed by `main.py`; loops when finished. |
| `requirements.txt`     | Pinned dependencies.                                             |
| `.venv/`               | Local virtual environment (git-ignored).                         |

There is no `pyproject.toml`, no packaging, no CI, and no test suite — the two
scripts are the entire application.

## Environment and dependencies

- Python 3 (the included `.venv` uses Python 3.14.7).
- Dependencies (from `requirements.txt`): `opencv-python==5.0.0.93`, `cvzone==2.0.0`,
  `numpy==2.5.1`.

Setup:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Run commands

Both scripts open GUI windows via `cv2.imshow`, so they require a display (they will
not work headless). Run them from the project root, since asset paths
(`carPark.mp4`, `image.png`, `CarParkingPosition`) are relative to the current
working directory.

```bash
# 1. (Only needed once, or to change the layout) mark parking spaces:
python ParkingSpacePicker.py

# 2. Run the counter on the video:
python main.py
```

Stop either script by closing its window / interrupting the process (Ctrl+C); there
is no quit-key handling.

## Testing

There are no tests, no test framework, and no lint/format configuration in this
project. Verification is manual: run `main.py` and visually check that free spaces
are outlined green, occupied ones red, and the `free: N/total` counter is correct.

## Code style and conventions

- Plain procedural scripts (no classes, no `main()` guard); module-level code runs
  on import.
- `camelCase` for most variables and functions (e.g. `checkParkingSpace`,
  `parkingPositionList`, `imgThresholdInv`).
- Comments/docstrings are in English and sparse; keep it that way.
- Tunable constants live at the top of the scripts: parking-space size
  (`width, height = 107, 48`) and the free-space pixel-count threshold (`1000` in
  `main.py`). If the input video or camera angle changes, these and the picked
  positions must be re-adjusted together.
- Positions are persisted with `pickle`; `CarParkingPosition` is binary data, not
  source code — do not edit it by hand, regenerate it with `ParkingSpacePicker.py`.
- Both scripts use bare `except:` when loading the pickle file (treating a
  missing/corrupt file as "no positions yet"); preserve that behavior when editing
  the loading logic.

## Security considerations

- `CarParkingPosition` is loaded with `pickle.load`, which can execute arbitrary
  code. Never load a pickle file from an untrusted source; only use files generated
  locally by `ParkingSpacePicker.py`.
- The project has no network surface, secrets, or user input beyond mouse clicks.
